## 2. جرد الحالة الحالية في المستودع

### 2.1 مركز الإعدادات — `SettingsHubScreen`

- ملف: `lib/ui/screens/settings/settings_hub_screen.dart`
- الشكل: قائمة `ListTile` عمودية (9 عناصر) بدون أقسام وكروت ومفاتيح.
- العناصر الحالية بالترتيب:
  1. اسم الشبكة → `NetworkNameSettingsScreen` (صفحة مستقلة)
  2. إعدادات الشريحة → `SimSettingsScreen`
  3. البطارية → `BatterySettingsScreen`
  4. قوالب التحويل → `TemplatesScreen`
  5. تصدير السجل → `ExportLedgerScreen`
  6. تنظيف السجلات → `CleanLogsScreen`
  7. تجديد الاشتراك → `RenewSubscriptionScreen`
  8. تفعيل الترخيص → `ActivationScreen`
  9. مركز المساعدة → `HelpCenterScreen`

### 2.2 مفاتيح الإعدادات الموجودة — `SettingKeys`

| المفتاح | الاستخدام الحالي |
|---------|------------------|
| `network_name` | اسم الشبكة في Header اللوحة |
| `preferred_sim_slot` | فتحة SIM المفضلة |
| `sms_listen_enabled` | تفعيل الاستماع لـ SMS (شاشة الشريحة) |
| `battery_optimization_acknowledged` | إقرار توصية البطارية |
| `default_currency` / `reservation_minutes` / `last_export_at` | داخلية/نسخ احتياطي |

**غير موجود:** مفاتيح للإعدادات الثلاثة الظاهرة في المرجع (المعالجة التلقائية، مبالغ الفئات فقط، الرسائل القديمة عند التوقف).

### 2.3 اسم الشبكة

- الحفظ والقراءة عبر `SettingsRepository` تحت `SettingKeys.networkName` — **موجود ويعمل**.
- PD-02: الافتراضي `NET`؛ يظهر في Dashboard Header.
- **الفجوة البصرية/التفاعلية:** صفحة مستقلة بدل كرت داخل الإعدادات + Bottom Sheet «تعديل اسم الشبكة» مع شرح استخدام الاسم في رسائل SMS.

### 2.4 مسار الرسائل (للربط لاحقًا — ليس واجهة هذه الخطة وحدها)

- `IncomingSmsHandler`: حفظ → تحليل → معالجة؛ `start()` / `stop()` على جسر SMS.
- `SettingKeys.smsListenEnabled` يُحفظ من شاشة الشريحة؛ **التحقق من أن `IncomingSmsHandler.start/stop` يقرآن هذا المفتاح عند التشغيل** جزء من ربط الإعدادات وليس من رسم الواجهة فقط.
- `LocalMessageRecoveryService`: يعيد معالجة `received` / `parsed` فقط (من business-rules).
- لا يوجد في Domain حاليًا مفتاح أو فرع صريح لـ «مبالغ الفئات فقط» أو «معالجة الرسائل القديمة عند التوقف» كإعداد مستخدم.

### 2.5 مركز المساعدة — `HelpCenterScreen`

- ملف: `lib/ui/screens/help_center_screen.dart`
- محتوى ثابت offline: 5 `ExpansionTile` فقط:
  - العملاء
  - الرصيد والتحويل
  - البيع
  - الترخيص
  - SMS (جملة واحدة عن الإذن والحفظ والتحليل والاستعادة)
- **لا يشرح** الإعدادات الثلاثة الناقصة، ولا أقسام النظام، ولا المحافظ/القوالب، ولا مسار البيع اليدوي بالتفصيل.

## 3. الهدف البصري لشاشة الإعدادات (من المرجع)

من تقرير الفروقات واللقطة المرجعية:

| عنصر الواجهة | المطلوب |
|--------------|---------|
| عنوان الصفحة | **الإعدادات** |
| وصف تحت العنوان | **تخصيص النظام وإدارة البيانات** |
| قسم | **النظام** |
| شكل العناصر | **كروت** (أيقونة + عنوان + وصف + قيمة أو `Switch`) وليست `ListTile` فقط |
| اسم الشبكة | كرت يعرض **القيمة الحالية**؛ الضغط → **Bottom Sheet** «تعديل اسم الشبكة» (شرح SMS + حقل + حفظ/إلغاء) |
| المعالجة التلقائية للرسائل | كرت + **مفتاح** تشغيل/إيقاف |
| معالجة مبالغ الفئات فقط | كرت + **مفتاح** |
| معالجة الرسائل القديمة عند التوقف | كرت + **مفتاح** |

عناصر أخرى موجودة في المشروع (شريحة، بطارية، قوالب، تصدير، تنظيف، اشتراك، ترخيص، مساعدة) تبقى ضمن الخطة كـ **إعادة تنظيم بصري/تنقل** تحت أقسام مناسبة، دون حذف وظائف موجودة، ما لم يقرر المنتج إخفاءها عن المرجع.

## 4. خطة البناء عنصرًا بعنصر — الإعدادات

### المرحلة S0 — قرارات منتج إلزامية قبل الكود (أسئلة مفتوحة)

لا تُخَمَّن الإجابات. تُثبَّت في `product-decisions.md` ثم يُنفَّذ.

| # | السؤال | لماذا ضروري |
|---|--------|-------------|
| Q1 | القيمة **الافتراضية** لكل من: المعالجة التلقائية، مبالغ الفئات فقط، الرسائل القديمة عند التوقف (`true`/`false`)؟ | تحديد حالة المفتاح عند أول تشغيل |
| Q2 | هل «المعالجة التلقائية» = نفس `sms_listen_enabled` أم مفتاح **مستقل** عن إعداد الشريحة؟ | المرجع يعرض كرتًا منفصلًا؛ المشروع لديه استماع SMS في شاشة الشريحة |
| Q3 | عند إيقاف المعالجة التلقائية: هل تُرفض الرسائل الواردة فورًا، أم تُحفظ كـ `received` دون معالجة، أم يُوقف الاستماع من الجسر؟ | أثر على `IncomingSmsHandler` / `SmsBridge` |
| Q4 | «مبالغ الفئات فقط»: عند عدم مطابقة المبلغ لفئة نشطة — `rejected` أم `failed` أم تعليق بحالة أخرى؟ وهل تُسجَّل Audit؟ | أثر على `TransferProcessor` / Parser |
| Q5 | «الرسائل القديمة عند التوقف»: هل تعني استدعاء `MessageRecovery` عند إقلاع التطبيق فقط عندما يكون المفتاح ON؟ وهل تُعالَج `failed` أيضًا أم `received`+`parsed` فقط (كما في الاستعادة الحالية)؟ | أثر على مسار الاستعادة |
| Q6 | نص شرح Bottom Sheet لاسم الشبكة: هل المعتمد «الاسم يُستخدم في نهاية رسائل SMS المرسلة للعملاء» كما في المرجع؟ | نسخة الواجهة |
| Q7 | ترتيب الأقسام النهائي في صفحة الإعدادات (النظام فقط أم نظام + بيانات + ترخيص + …) وعناصر المرجع التي تبقى مخفية تحت قائمة ثانوية؟ | هيكل الصفحة |
| Q8 | محتوى مركز المساعدة الكامل: هل يوجد نص مرجعي أطول من اللقطات أم نوسّع من business-rules + PD فقط؟ | نطاق Help |

**قاعدة التنفيذ:** أي بند يعتمد على Q1–Q5 لا يُدمج في `main` كسلوك إنتاج قبل تسجيل القرار في `product-decisions.md`.

### المرحلة S1 — هيكل صفحة الإعدادات (UI shell)

**الهدف:** استبدال قائمة `ListTile` بصفحة مطابقة للمرجع (عنوان + وصف + قسم النظام + كروت).

| مهمة | القبول |
|------|--------|
| عنوان «الإعدادات» + وصف «تخصيص النظام وإدارة البيانات» | مطابق للنص المرجعي |
| قسم «النظام» يضم على الأقل: اسم الشبكة + المفاتيح الثلاثة (واجهة) | تخطيط كروت |
| مكوّن مشترك للكرت: أيقونة، عنوان، وصف قصير، قيمة نصية أو `Switch` | إعادة استخدام |
| حالات: تحميل أولي للإعدادات، خطأ قراءة مع إعادة محاولة | لا تفاعل على المفاتيح أثناء التحميل |
| الإبقاء على مداخل الوظائف الموجودة (شريحة، بطارية، قوالب، تصدير، تنظيف، اشتراك، ترخيص، مساعدة) تحت أقسام أو كروت لاحقة دون كسر التنقل الحالي | لا حذف صامت لمسار موجود |

**ملفات متوقعة:** إعادة كتابة `settings_hub_screen.dart` ± ودجات `lib/ui/widgets/settings/`.

### المرحلة S2 — كرت اسم الشبكة + Bottom Sheet

**الهدف:** مطابقة المرجع بصريًا مع الإبقاء على مصدر الحقيقة الحالي.

| مهمة | القبول |
|------|--------|
| الكرت يعرض الاسم الحالي من `SettingsRepository` / افتراضي `NET` | قيمة حقيقية |
| الضغط يفتح Bottom Sheet: عنوان «تعديل اسم الشبكة»، شرح (بعد Q6)، حقل، حفظ، إلغاء | لا حفظ عند الإلغاء |
| الحفظ عبر `SettingsRepository.save(SettingKeys.networkName)` | كما PD-02 |
| بعد الحفظ: إغلاق الـ Sheet وتحديث قيمة الكرت | بدون بقاء قيمة قديمة |
| Dashboard Header يعيد التحميل عند العودة من الإعدادات (موجود جزئيًا — التحقق) | اسم محدَّث في اللوحة |
| إزالة أو الإبقاء على `NetworkNameSettingsScreen` كمسار عميق اختياري فقط إن لزم للتنقل القديم | لا ازدواجية مربكة للمستخدم |

**لا يُنفَّذ** إرسال SMS فعلي من هذا الكرت؛ الشرح نصي فقط حتى يثبت مسار قوالب رسائل العملاء لاحقًا.

### المرحلة S3 — المفاتيح الثلاثة (بعد S0)

#### S3.1 مفاتيح التخزين

إضافة إلى `SettingKeys` (أسماء مقترحة للتثبيت في القرار، ليست سلوكًا نهائيًا):

- `sms_auto_processing_enabled` — أو دمج مع `sms_listen_enabled` حسب Q2
- `process_category_amounts_only`
- `process_old_messages_on_resume`

القيم: `"true"` / `"false"` كنص في `AppSetting` (نمط المشروع الحالي).

#### S3.2 واجهة المفاتيح

| مهمة | القبول |
|------|--------|
| كل مفتاح في كرت مع عنوان ووصف من المرجع | RTL + خط Tajawal |
| تبديل المفتاح يحفظ فورًا عبر `SettingsRepository` | أو تأكيد حسب قرار المنتج |
| منع الضغط المزدوج أثناء الحفظ | حالة busy |
| فشل الحفظ: إظهار الخطأ وإرجاع المفتاح للقيمة السابقة | لا كذب بصري |
| نجاح اختياري: SnackBar أو مؤشر خفيف | متسق مع باقي الإعدادات |

#### S3.3 الربط السلوكي (Domain / Application)

| الإعداد | الربط المطلوب بعد قرار المنتج |
|---------|--------------------------------|
| المعالجة التلقائية | `IncomingSmsHandler.start/stop` و/أو تخطي `_process` عند OFF حسب Q3 |
| مبالغ الفئات فقط | فرع في مسار التحويل/المعالجة: رفض أو تعليق المبلغ غير المطابق لفئة نشطة حسب Q4 |
| الرسائل القديمة عند التوقف | عند إقلاع/استئناف التطبيق: استدعاء مسار الاستعادة فقط إذا ON، وفق نطاق الحالات في Q5 |

**اختبارات إلزامية بعد الربط:** تغيير المفتاح يغيّر السلوك (وحدة/تكامل)، وليس حفظ القيمة في الجدول فقط.

### المرحلة S4 — تنظيم بقية مداخل الإعدادات الحالية

إعادة عرض (كروت أو قسم «بيانات» / «الجهاز» / «الحساب») دون تغيير عقود الشاشات الفرعية إلا عند وجود لقطة مرجعية لاحقة:

| المدخل الحالي | الإجراء في هذه الخطة |
|---------------|----------------------|
| إعدادات الشريحة | الإبقاء؛ توضيح العلاقة مع «المعالجة التلقائية» بعد Q2 |
| البطارية | الإبقاء كمدخل |
| قوالب التحويل | الإبقاء كمدخل (معالج فوسك الكامل خارج النطاق) |
| تصدير السجل | الإبقاء |
| تنظيف السجلات | الإبقاء؛ **ليس** بديلًا عن مفتاح الرسائل القديمة |
| تجديد الاشتراك / تفعيل الترخيص | الإبقاء |
| مركز المساعدة | يفتح الشاشة بعد المرحلة H |

## 5. خطة البناء — مركز المساعدة

### 5.1 الوضع الحالي

محتوى قصير جدًا؛ لا يغطي الإعدادات التشغيلية ولا مسارات PD الأخيرة (بيع يدوي، بانر الرسائل، إلخ).

### 5.2 الهدف

مركز مساعدة **offline** يشرح سلوك النظام كما هو موثّق في المستودع والقرارات — **بدون اختراع ميزات**.

### 5.3 هيكل مقترح للمواضيع (يُحدَّث نصًا بعد Q8)

مواضيع مبنية على ما هو موثّق فعلًا:

| الموضوع | أساس المحتوى (مصادر موجودة) |
|---------|------------------------------|
| لوحة التحكم | PD-01…04: الرصيد المعلق، المبيعات، البانر، الهيدر |
| العملاء والرصيد | business-rules + Help الحالي |
| البيع من الرصيد والبيع اليدوي | business-rules + PD-06 |
| الرسائل وSMS | Help الحالي + مسار save→parse→process + الاستعادة |
| الإعدادات التشغيلية | يُضاف **بعد** تثبيت S0 وS3 — يشرح أثر كل مفتاح كما في القرار |
| الترخيص | Help الحالي |
| المخزون والكروت | business-rules (FIFO / حجز) |

### 5.4 واجهة Help

| مهمة | القبول |
|------|--------|
| عنوان «مركز المساعدة» | موجود |
| قائمة مواضيع قابلة للتوسيع أو أقسام | قراءة سهلة RTL |
| لا محتوى remote | offline-first |
| دخول من Header اللوحة ومن الإعدادات | المسارات الحالية تبقى |
| تحديث النصوص عند اعتماد قرارات إعدادات جديدة | لا تتعارض مع PD |

## 6. ترتيب التنفيذ المعتمد لهذه الخطة

```text
S0  قرارات المنتج (Q1–Q8) → تسجيل في product-decisions.md
S1  هيكل صفحة الإعدادات + كروت القسم «النظام»
S2  كرت اسم الشبكة + Bottom Sheet (منطق الحفظ موجود)
S3  المفاتيح الثلاثة: تخزين + UI + ربط Domain/Application + اختبارات
S4  إعادة تنظيم مداخل الإعدادات المتبقية
H1  توسيع مركز المساعدة من المصادر الموثّقة فقط
H2  فقرة إعدادات تشغيلية في Help بعد اكتمال S3
docs تحديث progress.md بعد كل مرحلة مكتملة
```

لا يُعتبر عنصر «مكتملًا» إلا: قرار (إن لزم) + UI مطابق + مصدر بيانات حقيقي + تفاعل + تحديث progress.

## 7. معايير القبول الإجمالية (Settings + Help)

1. صفحة الإعدادات تعرض عنوانًا ووصفًا وقسم «النظام» وكروتًا وليس قائمة مسطحة فقط.
2. اسم الشبكة: قيمة ظاهرة في الكرت + Sheet تعديل + حفظ محلي + انعكاس على Header.
3. المفاتيح الثلاثة: ظاهرة، محفوظة، وتُغيّر سلوك الرسائل وفق قرارات S0 (مع اختبارات).
4. لا Mock لأرقام أو حالات إعدادات في وضع المنتج.
5. مركز المساعدة يغطي المواضيع الموثّقة ويُحدَّث بعد قرارات الإعدادات.
6. لا يشمل هذا الإصدار معالج قوالب فوسك / محافظ-POS الكامل / قوالب رسائل العملاء (ملف لاحق).

## 9. خلاصة

- التقرير المرفق يحدد بوضوح أن شاشة الإعدادات **غير مطابقة** للمرجع: ينقص الشكل (كروت/قسم نظام) وثلاثة إعدادات تشغيلية وسلوك Sheet لاسم الشبكة.
- مركز المساعدة الحالي **لا يشرح النظام بالكامل**؛ لا يجوز استنتاج سلوك المفاتيح الناقصة منه.
- هذه الخطة تغطي **الإعدادات + المساعدة فقط**، وتوقف التنفيذ السلوكي للمفاتيح الثلاثة عند حدود الأسئلة المفتوحة حتى يثبّتها صاحب المنتج في `product-decisions.md`.
