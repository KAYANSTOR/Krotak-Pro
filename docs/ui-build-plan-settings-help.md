## 0. حالة التنفيذ الحالية (لا تُعاد)

| المرحلة | الحالة | ملاحظة |
|---------|--------|--------|
| **S0** قرارات Q1–Q8 | ✓ | PD-07 / PD-08 |
| **S1** هيكل الإعدادات 6 أقسام + كروت | ✓ | `settings_hub_screen.dart` |
| **S2** كرت اسم الشبكة + Sheet | ✓ | نص SMS المعتمد |
| **S3** ربط Domain للمفاتيح الثلاثة | ✗ | **مطلوب في هذه الدفعة** |
| **P** الرسائل المعلّقة | ✗ | مرتبطة بـ «مبالغ الفئات فقط» |
| **R** الرسائل المرفوضة (مراجعة/أرشيف) | ✗ | PD-08 + مخرج الرفض من المعلّقة |
| **A** الحسابات والدفتر (تعميق) | جزئي | عملاء موجودون؛ الدفتر/مدين-دائن ناقص بصريًا |
| **C** إدارة الكروت / الفئات / استيراد / إضافة | جزئي | `InventoryScreen` + Domain؛ الواجهة المرجعية ناقصة |
| **H** مركز المساعدة الموسّع | ✗ | بعد تثبيت السلوك في S3/P/R/C |

**قاعدة الدفعة:** لا يُعتبر إعداد «مبالغ الفئات فقط» مكتملًا إلا مع شاشة المعلّقة + اعتماد/رفض + أثر في الدفتر. لا تُنفَّذ المفاتيح كواجهة فقط.

## 1. لماذا دفعة واحدة؟

```text
إعداد: معالجة مبالغ الفئات فقط = ON
  → مبلغ ≠ فئة نشطة
  → رسالة معلّقة (وليس rejected فورًا)     [PD-07 Q4]
  → اعتماد → إيداع لحساب العميل + Audit
  → رفض → رسائل مرفوضة مؤرشفة             [PD-08]

إعداد: المعالجة التلقائية = OFF
  → حفظ الرسائل بلا إيداع/بيع/إرسال        [PD-07 Q2/Q3]

إعداد: الرسائل القديمة عند التوقف = ON
  → عند الإقلاع: استعادة + منع التكرار     [PD-07 Q5]

المخزون / الفئات
  → تعريف «فئة مطابقة» و«لا مخزون» لأسباب الرفض والمعلّقة والبيع
```

أي فصل بين S3 وP وR وC يترك النظام غير متسق مع القرارات.

## 2. الدفعة B — ترتيب التنفيذ الجذري

```text
B1  S3 Domain: قراءة المفاتيح الثلاثة في مسار SMS/الاستعادة + اختبارات
B2  P  شاشة الرسائل المعلّقة (قائمة + بحث + بطاقة + اعتماد/رفض)
B3  R  شاشة الرسائل المرفوضة (PD-08: تصنيفات + بطاقات + أرشيف)
B4  A  تعميق الحسابات والدفتر (رصيد مدين/دائن + حركات حقيقية)
B5  C1 إدارة الفئات (مرجع صورة 44)
B6  C2 إدارة الكروت + إضافة فردي/مجموعة + استيراد PDF/Excel/CSV
B7  C3 مواءمة CardStockSheet مع المرجع (أرقام حقيقية — جزئيًا موجود)
B8  H  توسيع مركز المساعدة من PD + business-rules + السلوك المنفَّذ
B9  docs: تحديث progress.md بعد كل بند مكتمل
```

محافظ / معالج فوسك / محاكاة القوالب / قوالب رسائل العملاء = **دفعة لاحقة** (موصوفة في التقرير، خارج تنفيذ هذه الدفعة إلا إن طُلب صراحة).

---

## 3. B1 — S3 ربط Domain (المفاتيح الثلاثة)

### 3.1 مفاتيح (موجودة في `SettingKeys`)

| مفتاح | افتراضي | أثر |
|-------|---------|-----|
| `sms_auto_processing_enabled` | true | إن false: لا إيداع/بيع/إرسال تلقائي؛ الرسالة تُحفظ |
| `process_category_amounts_only` | true | إن true ومبلغ ≠ فئة: مسار معلّقة لا رفض مباشر |
| `process_old_messages_on_resume` | true | إن true عند الإقلاع: استعادة مع idempotency |

`sms_listen_enabled` يبقى **مستقلًا** (استقبال/حفظ فقط).

### 3.2 نقاط الربط في الكود

| نقطة | السلوك المطلوب |
|------|----------------|
| `IncomingSmsHandler` / `LocalTransferProcessor` | قراءة المفاتيح عبر `SettingsRepository` في كل معالجة |
| معالجة تلقائية OFF | بعد الحفظ: لا credit ولا reserve ولا send |
| مبالغ الفئات فقط | لا فئة بنفس faceValue → معلّقة للمراجعة (ليست rejected) |
| الإقلاع | إن process_old_messages_on_resume: recovery + منع التكرار |

### 3.3 اختبارات إلزامية

- OFF تلقائي: رسالة محفوظة بلا حركة مالية.
- فئة فقط + مبلغ غريب: معلّقة، لا بيع.
- استعادة: لا تكرار لنفس externalReference.

---

## 4. B2 — الرسائل المعلّقة (قيد التأكيد)

عنوان: **الرسائل المعلّقة (قيد التأكيد)** · بحث بجوال · قائمة · فراغ.

بطاقة: محفظة · جوال · مبلغ · مرجع · وقت · سبب · **اعتماد** / **رفض**.

اعتماد → إيداع لحساب موجود + Audit · لا كرت بلا فئة.
رفض → أرشيف المرفوضة.

---

## 5. B3 — الرسائل المرفوضة (PD-08)

عنوان + وصف مراجعة · فلاتر (الكل / فشل إرسال / لا مخزون) · بطاقة إجمالي + جديد · بطاقة رسالة (سبب، محفظة، جوال، مبلغ، وقت).

---

## 6. B4 — الحسابات والدفتر

بحث · بطاقة حساب (رصيد، مدين/دائن) · دفتر CREDIT/DEBIT/REVERSAL.
اعتماد المعلّقة يظهر في نفس حساب العميل.

---

## 7. B5–B7 — الفئات والكروت والاستيراد

**فئات:** بحث · فراغ · فئة جديدة (قيمة، عملة، عمولة).
**كروت:** فئات · استيراد PDF/Excel/CSV · إضافة فردي/مجموعة · منع بلا فئة نشطة.
**مخزون حسب الفئة:** أرقام حقيقية · الذهاب لإدارة الكروت.

---

## 8. B8 — مركز المساعدة

من PD + business-rules + السلوك المنفَّذ فقط: دورة SMS · معلّقة/مرفوضة · إعدادات · دفتر · مخزون/حجز.

---

## 9. معايير اكتمال الدفعة B

1. غير المطابق → معلّقة لا رفض مباشر
2. اعتماد → إيداع + دفتر
3. رفض → أرشيف مرفوضة
4. حساب بحركات حقيقية
5. كروت من مخزون حقيقي
6. لا كرت بلا فئة نشطة
7. استيراد بمعاينة وأخطاء
8. فئات مربوطة بالكروت
9. حجز يمنع البيع المزدوج
10. تحميل/نجاح/فشل/فراغ حقيقية

## 12. الخلاصة

- الخطة الضيقة (إعدادات+مساعدة فقط) **استُبدلت** بهذه الدفعة لأن اكتمال الإعدادات يشترط المعلّقة والمرفوضة والمخزون.
- **S0–S2 منجزة**؛ التنفيذ التالي = **B1 (S3 Domain)** ثم **B2 المعلّقة** دون فصل.
- لا يُغلق بند إعدادات الرسائل في progress إلا بعد B1+B2+B3 واختباراتها.
