## 2) الأساس (المرحلة 1)

- **الخط:** Tajawal (6 أوزان) مُضمَّن في `assets/fonts` ومسجَّل في `pubspec.yaml`.
  قبل ذلك كان الثيم يطلب `fontFamily: 'Tajawal'` بلا أي ملف خط ولا `assets/`، فكان كل النص
  العربي يُرسم بالخط الاحتياطي. حُذف الاعتماد غير المستخدم `google_fonts`.
- **رموز التصميم** (`lib/ui/theme/net_tokens.dart`): `NetSpacing`, `NetRadii`, `NetDurations`,
  `NetSizes`, `NetMotion` (يحترم `disableAnimations`), `NetElevation` (soft/raised/glow),
  `NetTypography` (سلّم خطوط بدل المقاسات العشوائية).
- **الثيم** (`net_theme.dart`): Card / Dialog / BottomSheet / SnackBar / Chip / Buttons /
  Divider / Progress / ListTile — فلن تحتاج الشاشات لتعريف الأشكال يدويًا.
- **الهوية اللونية:** تدرّج العلامة تعريف واحد (`KayanColors.brandGradient*`)، وأُضيف
  `info` / `infoContainer`، وأصبح `KayanPalette.primary` متاحًا للوضعين.
- **الألوان الدلالية** (`net_semantic_colors.dart`): `warning/warningContainer`،
  `rejected/rejectedContainer`، `available/availableContainer`، `sold/soldContainer`،
  `pending/pendingContainer`، `alertBackground/alertForeground` — نسخة لكل وضع، فلا تحتاج
  الشاشات لمعرفة الوضع الحالي.

## 4) ما نُفِّذ شاشة بشاشة

- **لوحة التحكم:** هيكل تحميل، بطاقة رصيد بتدرّج العلامة + عدّاد متحرك، مؤشرات مع **منحنى
  اتجاه آخر 7 أيام** (استعلام قراءة إضافي واحد)، شريط إجراءات أفقي (وأُزيل FAB المكرر)،
  تنبيهات قابلة للإخفاء وبانر للحالة الجزئية، وآخر العمليات مجمّعة باليوم مع تسميات عربية
  وأوقات نسبية.
- **التقارير:** 3 بطاقات KPI (مرفوضة/قيد المعالجة/فاشلة) من `OpsReportService`، بطاقة ملخص
  مبيعات، وصفوف مجمّعة بلون دلالي لكل قسم.
- **العروض:** تبويبات بعدّادات، بطاقة لكل عرض (عتبة/مكافأة/حالة)، أوراق موحّدة `NetSheet`،
  وحذف اللون البنفسجي الخارج عن الهوية (استُبدل بلون العلامة).
- **الحسابات:** شريط ملخص (إجمالي المدين/الدائن محسوبًا من الصفوف المحمّلة)، أفاتار حرف أول
  ثابت اللون، **تصحيح دلالي**: المديونية كانت تُعرض دائمًا بلون أخضر، الآن شارة رصيد دلالية
  (`NetBalancePill`)، فلاتر بعدّادات، و**زرّا «اتصال» و«رسالة»** يظهران عند وجود رقم جوال
  ويفتحان تطبيق النظام المناسب.
- **الكروت:** مقياس مخزون مقسّم (متاح/محجوز/مباع)، شرائح فئات بعدد المتاح، إخفاء/إظهار
  الرموز مع زر نسخ، وأوراق بثيم النظام.
- **سجل العمليات:** ملخص ثابت أعلى القائمة، فلتران (نوع/تاريخ) كشرائح، تجميع باليوم مع رؤوس
  أيام عربية، شريحة حالة لكل عملية، حالات تحميل هيكلية وحالة فارغة بزر «مسح الفلاتر».
- **الإعدادات:** بحث **يفلتر الصفوف نفسها** (`SettingsSearchScope`): الصف غير المطابق يُخفى،
  والمجموعة التي لا يتبقى فيها صف مطابق تُطوى مع رأسها، مع كلمات بديلة لكل صف (مثل «ليلي»
  للوضع الداكن)، + **بطاقة جاهزية التشغيل** (المعالجة التلقائية، تنبيه التدخل، سلفني، المظهر)
  مع رابط مباشر لفحص النظام + رأس بوصف.
- **معالج الصلاحيات:** شاشة واحدة بمؤشر تقدّم (1/N)، حالة تحقق حيّة لكل خطوة
  (تم التحقق / غير مفعّل / اختياري / جارٍ الفحص)، أزرار: التنفيذ، فتح الإعدادات، إعادة
  الفحص، والتالي — بدل سبعة حوارات مانعة متتالية.
- **شاشات الرسائل والقوالب والمحافظ:** كامل ألوانها الآن من رموز الثيم (لا نص أسود ثابت ولا
  خلفية باستيل فاتحة)، مع محاذاة العناوين وحالات التحميل/الفراغ الموحّدة.

## 6) ما لم يُنفَّذ (بأسباب موضوعية، لا نقص تنفيذ)

1. **شريط تقدّم لكل عرض ترويجي في شاشة العروض**: شاشة العروض تعرض *كتالوج* العروض
   (`Promotion` = عنوان + عتبة + مكافأة)، ولا يوجد فيها مبلغ تراكم للعميل. التقدّم الحقيقي
   موجود في `CustomerPromotionProgress` داخل شاشة العميل من بيانات فعلية. عرض شريط في
   الكتالوج كان سيتطلب حساب تجميعي جديد عبر كل العملاء (منطق + بيانات) أو أرقامًا وهمية —
   وكلاهما خارج النطاق المطلوب.
2. **انتقال Hero بين بطاقة الرصيد وسجل العمليات**: Hero يحتاج واجهة مقابل في الشاشة الهدف
   (بطاقة رصيد داخل شاشة السجل) وهي غير موجودة في تصميم الشاشة الهدف، وإضافتها تغيير تصميمي
   غير مطلوب. الانتقالات المتحركة الأخرى نُفِّذت (عدّاد المبالغ، رسم المنحنى، الأوراق).
3. **إجراءات الحساب الفردي (حذف/أرشفة)**: تغيير منطقي على البيانات — خارج النطاق المحدد.
4. **انتقال تبويبات المنصة الرئيسية بتلاشٍ متقاطع**: `HomeShell` يستخدم `IndexedStack` للحفاظ
   على حالة كل تبويب (تمرير/فلاتر). أي `AnimatedSwitcher` حوله يعيد بناء التبويبات ويفقد
   حالتها، فتُرك كما هو حفاظًا على السلوك.

### أ) تغطية إصلاح الوضع الداكن (فحوصات على الشجرة)

```bash
# 1) ألوان نص رمادية/كحلية ثابتة في lib/ui (بعد إصلاحها) = 0
grep -rnE "Color\(0xFF(0F172A|64748B|94A3B8|CBD5E1|475569|…)\)" lib/ui | grep -v theme/ | wc -l
→ 0

# 2) خلفيات باستيل/فاتحة ثابتة في كود الشاشات = 0
grep -rnE "0xFF[EF][0-9A-Fa-f]{5}" lib/ui | grep -v theme/
→ لا شيء (بقي فقط لونان محافظان على الوضع *E8F5F5* محميّان بـ isDark)

# 3) لا استخدام مجرّد لـ netColors خارج build (سبب undefined_identifier)
grep -rn "netColors" lib/ui | grep -v "context\.netColors" | grep -v theme/net_semantic_colors.dart
→ لا شيء
```

### ب) بوابة CI هي التحقق الحقيقي

هذه البيئة لا تحتوي Flutter/Dart SDK، لذا لم تُشغَّل الأوامر محليًا؛ بدلًا من ذلك **نفّذتها
GitHub Actions فعليًا على كل دفعة** (workflow: `.github/workflows/ci.yml`، Flutter 3.47.4):

```
flutter pub get
flutter analyze --no-fatal-infos     → No issues found
flutter test                        → كل الاختبارات نجحت
flutter build apk --release         → APK + GitHub Release
```

(ويشمل تبعية `url_launcher` الجديدة وإدخالات `<queries>` في `AndroidManifest.xml`).
