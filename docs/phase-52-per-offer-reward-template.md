# مرحلة 52 — قالب مكافأة مستقل لكل عرض

**التاريخ:** 2026-10-02  
**الأصل:** البند المؤجّل في المرحلة 48 («قالب مستقل لكل عرض»).

## القرار

القالب العام يبقى افتراض كل العروض. أي عرض يمكن أن يملك نص رسالة مكافأة خاصاً به دون تغيير بقية العروض.

## التنفيذ

- الإعداد `promotion_reward_sms_templates` خريطة JSON بمعرّف العرض.
- صرف المكافأة يقرأ قالب العرض أولاً، ثم القالب العام، ثم النص الافتراضي.
- مسح النص وحفظه يحذف التخصيص ويعيد العرض إلى القالب العام.
- زر الرأس يبقى لمسار القالب العام. قائمة العرض تفتح قالب هذا العرض فقط.
- `{promotion_name}` و`{reward_value}` و`{amount}` تُستبدل عند الإرسال.

## خارج النطاق

- قالب مستقل لكل عميل داخل العرض نفسه.
- التحقق الميداني للرسالة على جهاز حقيقي يبقى عند المالك.
