## 1. حالات الرسائل المعلقة (من لقطة مركز الاسترداد)

| الحالة في الصور | المعنى | المكافئ المقترح في Domain |
|-----------------|--------|---------------------------|
| انتظار تأكيد الشبكة | تم الإرسال وبانتظار تقرير التسليم | `confirmPending` (أو الإبقاء على `sending` + حقل فرعي) |
| PENDING | جاهزة لإعادة المحاولة التلقائية | `pending` |
| SENDING | جاري الإرسال | `sending` |
| FAILED_MAX_RETRIES | استنفاد 3 محاولات | `failedMaxAttempts` |

**قواعد من الصور:**
- الحد الأقصى للمحاولات: **3**
- الاسترداد الذاتي: إذا بقيت الرسالة في انتظار التأكيد **أكثر من 15 دقيقة** دون رد من الشبكة → إعادة إدراجها في طابور الإرسال
- إجراءات يدوية: إعادة إرسال / تأكيد صرف يدوي (اعتماد القيد) / تراجع كامل (تحرير الحجز + إلغاء قيد الإيداع)

**الحالة الحالية في الكود:**  
`MessageProcessingStatus` يتضمن `pending`, `sending`, `failedMaxAttempts`, `recovered` (بعد Phase 1).  
لم يُنفَّذ بعد: مهلة 15 دقيقة، ولا تمييز صريح لـ confirmPending إن لزم.

## 2. أكواد الرفض الـ 13 (عقد ثابت)

| Code | المعنى |
|------|--------|
| `voucherSendFailed` | فشل إرسال الكرت بعد استنفاد المحاولات |
| `voucherUnavailable` | لا يوجد مخزون كروت كافٍ في الفئة المطلوبة |
| `missingFields` | بيانات أساسية مفقودة في الرسالة |
| `categoryMismatch` | المبلغ لا يطابق أي فئة كروت نشطة |
| `blacklisted` | رقم جوال العميل مدرج في القائمة السوداء |
| `parseFailure` | فشل قواعد القالب في قراءة نص الرسالة |
| `noActiveTemplate` | المحفظة ليس لها قوالب نشطة |
| `unknownSender` | رسالة واردة من جهة أو محفظة غير مسجلة |
| `duplicateTransaction` | عملية تحويل مكررة بنفس البصمة |
| `invalidFormat` | تنسيق الرسالة غير صالح أو تجاوز الحد المسموح |
| `licenseBlocked` | الترخيص منتهٍ أو رصيد الرسائل نفد |
| `creditLimitExceeded` | نقطة البيع تجاوزت سقف الدين المسموح به |
| `other` | سبب استثنائي آخر |

**مطلوب:** ثابت Domain واحد (`RejectionCodes`) يطابق هذه الأسماء؛ ربط واجهة الرسائل المرفوضة والإجراءات السريعة بهذه الأكواد.

## 3. قواعد نقاط البيع (POS)

- سقف دين مسموح به لكل نقطة (Credit Limit بالريال اليمني)
- طلب كروت متعددة في رسالة واحدة: **حد أقصى 3 كروت** لكل رسالة؛ أكثر من ذلك → رفض
- نسبة عمولة/خصم لكل فئة سعرية تُطبَّق تلقائيًا ويُقيَّد الصافي فقط
- فحص قبل الصرف: المديونية الحالية + المبيعات الجديدة ≤ سقف الدين
- تجاوز السقف → رسالة `POS_CREDIT_LIMIT_EXCEEDED`
- تسوية يدوية (سداد / تصحيح) + تسوية تلقائية من حوالة محفظة برقم جوال النقطة
- استعلام رصيد برمز افتراضي **111** → `POS_BALANCE_RESPONSE`
- ملخص يومي تلقائي → `DAILY_POS_SUMMARY`

---

## 4. سلفني (من اللقطات)

- التفعيل من الإعدادات
- أهلية: مشترك مسجّل مسبقًا، غير محظور، رصيد **صفر تمامًا**، ومخزون فئة سلفني متوفر
- أمر الرسالة: كلمة «سلفني» أو الحرف «س» فقط (مطابقة صارمة)
- مرة واحدة حتى سداد كامل قيمة الكرت السابق
- عند أي إيداع لاحق: اقتطاع دين سلفني أولًا ثم إصدار كرت بالمتبقي إن وُجدت فئة مطابقة
- قالب التسليم: `SALAFNI_VOUCHER_DELIVERY` + قيد DEBIT

## 6. النسخ الاحتياطي (مواصفات الصورة)

- كلمة مرور ≥ 4 أحرف
- **AES-GCM 256-bit**
- اشتقاق مفتاح: **PBKDF2** مع **10,000** دورة + **SHA-256** للبصمة
- حفظ تلقائي في مجلد `ZNet_Backups` بصيغة `.znet`
- الاستعادة تستبدل بيانات التطبيق الحالية، مع **الحفاظ على عداد الترخيص بأمان**

## 7. سياسة الاحتفاظ في التنظيف الذكي

## 8. قواعد إضافية من Pipeline والواجهة

- فشل SMS مؤقت → طابور قيد التأكيد حتى 3 محاولات (لا صرف كرت بديل تلقائيًا)
- دين سابق على العميل → اقتطاع قيمة الدين أولًا وإصدار كرت بالمبلغ الصافي المتبقي فقط
- Monitoring SIM منفصلة عن Sending SIM + Auto-Failover مع تسجيل الشريحة في كل محاولة
- BootReceiver + Service Watchdog + استثناءات البطارية (خصوصًا Samsung / Xiaomi / Huawei)
- منع تعديل رصيد العميل يدويًا إن وُجدت رسالة معلقة بانتظار تأكيد الشبكة
- حذف عميل = تنظيف ذري متسلسل بعد تحذير نهائي

## 10. معيار اكتمال المطابقة

1. دورة Pipeline + الحجز الذري + منع التكرار خضراء باختبارات إيقاف/إعادة تشغيل
2. حالات المعلقة والرفض تطابق الأسماء والسلوك أعلاه
3. POS (سقف، 3 كروت، تسوية، 111) يعمل من مصادر حقيقية
4. Backup/Restore بالمواصفات أعلاه يُستعاد على جهاز آخر بنفس الأرصدة
5. لا أرقام ثابتة في Dashboard؛ كل KPI من قاعدة البيانات
