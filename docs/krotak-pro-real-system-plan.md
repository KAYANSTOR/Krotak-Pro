# خطة تحويل منطق Krotak Pro الظاهر في اللقطات إلى نظام حقيقي قابل للإصدار

**نطاق الوثيقة:** هذه الوثيقة هي مرجع التنفيذ. تم اعتمادها كخط أساس في 2026-09-17 بعد استعادة `main` إلى `95865c9`.

## 1. الحكم التنفيذي

الأرشيف المرفق ليس مجموعة صور تجميلية أو صور شاشة للمساعد، بل يحتوي على 14 لقطة طويلة من **مركز المساعدة والتشغيل الفعلي**. اللقطات تصف سلوك النظام المتوقع في استقبال الرسائل، ومنع التكرار، والتحليل، والتحقق من الحظر، وفحص رصيد نقاط البيع، وتسوية الديون، وحجز الكرت، والتسجيل المحاسبي، والإرسال، وإعادة المحاولة، والاسترداد، والتقارير، والنسخ الاحتياطي، والتنظيف، وإعدادات الشرائح والـ SMS، وخدمة سلفني، وتسليم الكروت، ومركز الرسائل المعلقة والمرفوضة.

المستودع الحالي ليس فارغًا. هو يحتوي على طبقات Domain وData وServices وواجهات متعددة، كما توجد خدمات بأسماء مطابقة لعدد كبير من العمليات المذكورة في اللقطات. لكن الحالة الحالية هي **Feature Foundation متقدم، وليس إصدارًا إنتاجيًا مكتملًا**.

السبب الرئيس ليس غياب كل الوظائف، بل أن بعض الوظائف موجودة كخدمات محلية أو أساس أولي دون اكتمال ضمانات النظام الكاملة. كما أن توثيق المشروع نفسه يسجل تعارضات بين عقود المستودعات والخدمات والاختبارات. لذلك لا ينبغي البدء بإضافة واجهات جديدة أو ميزات ثانوية قبل تثبيت النواة المالية ودورة الرسائل.

> الترتيب الصحيح: تثبيت العقود والفحوص، ثم جعل دورة الرسالة والعملية المالية ذرية وقابلة للاستعادة، ثم إكمال تكامل Android، ثم ربط الواجهات والتقارير، وبعد ذلك فقط الإطلاق التجريبي.

## 2. ما الذي تثبته اللقطات الأصلية؟

### 2.1 دورة الرسالة والعملية المالية

```text
SMS وارد
  → SmsReceiver
  → حفظ خام في طابور آمن
  → توليد بصمة ومنع التكرار
  → التعرف على المرسل والقالب
  → تحليل الحقول
  → فحص الرقم المحظور
  → فحص توفر الكرت وحدود فئة POS
  → فحص الدين والائتمان
  → حجز الكرت ذريًا
  → إنشاء قيد Debit/بيع
  → تحديث الدين أو الرصيد
  → تسجيل النقاط/العرض
  → إرسال كود الكرت عبر SIM المرسلة
  → تسجيل نتيجة الإرسال
  → إعادة المحاولة أو التحويل إلى Pending/Failed
  → إظهار العملية في السجل والتقارير
```

### 2.2 حالات الرسائل (المطلوبة)

| الحالة | المعنى المطلوب |
|---|---|
| `RECEIVED` | الرسالة وصلت وحُفظت ولم تبدأ معالجتها بعد |
| `PARSED` | تم استخراج الحقول وقبول شكل الرسالة |
| `PENDING` | تحتاج إعادة محاولة أو مراجعة بسبب نقص مؤقت |
| `SENDING` | النظام في مرحلة إرسال النتيجة للعميل |
| `PROCESSED` | اكتملت المعالجة والتسجيل والإرسال المطلوب |
| `FAILED_MAX_ATTEMPTS` | انتهت المحاولات دون نجاح |
| `REJECTED` | رُفضت بسبب قاعدة عمل معروفة |
| `RECOVERED` | استُعيدت من حالة معلقة وأعيدت معالجتها بأمان |

يجب أن تكون انتقالات الحالة محددة في Domain State Machine.

### 2.3–2.5 اللوحة، التقارير، Android

لوحة من مصادر حقيقية، تقارير قابلة للتصفية، وتشغيل SMS/Boot/SIM/Battery على أجهزة فعلية.

## 3–4. الجرد والفجوات الحرجة

الفجوات بالأولوية:
1. عدم ثبات عقود الطبقات
2. الذرية المالية
3. idempotency على مستوى قاعدة البيانات
4. عدم اكتمال Android Runtime
5. النسخ الاحتياطي والاستعادة المشفرة الآمنة

## 5. خطة التنفيذ المرحلية

- **المرحلة 0:** التجميد والجرد (هذا التقرير + baseline)
- **المرحلة 1:** تثبيت العقود والفحوص
- **المرحلة 2:** مخطط البيانات والمهاجرات + قيود فريدة
- **المرحلة 3:** محرك العملية الذرية
- **المرحلة 4:** طابور الرسائل وإعادة الاسترداد
- **المرحلة 5:** تكامل Android والجهاز
- **المرحلة 6:** النسخ الاحتياطي والصيانة
- **المرحلة 7:** ربط الواجهات والتقارير
- **المرحلة 8:** التفعيل والإصدار التجريبي

## 6. مصفوفة اختبارات القبول

الرسائل، المخزون، الدين، الإرسال، الاسترداد، Android، البيانات، الواجهة، التقارير، الأمان — كما في الوثيقة الأصلية.

## 7–10. الموجود / المفقود، ما لا ينبغي فعله، ترتيب Sprint الأول، الخلاصة

لا ميزات Post-V1 قبل تثبيت دورة البيع. لا إصدار تجاري قبل فحوص الجهاز والاستعادة.

**التصنيف:** نظام أولي متقدم قيد التثبيت.
