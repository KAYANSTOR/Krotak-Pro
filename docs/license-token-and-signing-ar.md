# مفاتيح الترخيص وتوقيع التطبيق

## ما تم إصلاحه

- لم يعد حقل التفعيل يقبل معرّفًا عشوائيًا أو يمنح ترخيصًا دائمًا.
- رمز الترخيص الآن بصيغة `KRT1` وموقّع بـ **Ed25519**.
- التطبيق يحتوي على المفتاح العام فقط للتحقق؛ المفتاح الخاص لا يدخل المستودع ولا الـAPK.
- الرمز يحفظ في الإعداد الداخلي `license_token` ولا يدخل لقطة إعدادات النسخ الاحتياطي.
- تعديل الرمز أو توقيعه أو تاريخ انتهائه يؤدي إلى رفضه.
- التجديد يتم بإدخال رمز جديد صادر من الإدارة، وليس بإنشاء مدة محلية قابلة للتلاعب.
- CI يرفض بناء نسخة نشر إذا غابت أسرار المفتاح التجاري، ولا يسمح بإنتاج APK تحديث غير متوافق على `main`.

## إصدار رمز ترخيص

احفظ المفتاح الخاص الإداري خارج Git وبصلاحيات `600`، ثم استخدم:

```bash
python3 tools/license_token.py \
  --private-key /secure/path/krotak-license-private.key \
  --license-id NET-2026-0001 \
  --days 30
```

لترخيص غير منتهٍ:

```bash
python3 tools/license_token.py \
  --private-key /secure/path/krotak-license-private.key \
  --license-id NET-2026-0001 \
  --perpetual
```

يُرسل الناتج للمشترك عبر قناة آمنة. لا تضعه في GitHub Issues أو السجلات العامة.

## مفتاح توقيع Android

يجب أن تكون القيم التالية في GitHub Secrets لبناء `main`:

- `APK_KEYSTORE_B64`
- `APK_KEY_ALIAS`
- `APK_KEYSTORE_PASSWORD`
- `APK_KEY_PASSWORD`

كل APK إنتاجي يجب أن يستخدم نفس keystore التجاري. أما بناءات Pull Request فتستخدم مفتاح CI مؤقتًا للاختبار فقط، ولا تصلح كتحديث فوق النسخة التجارية.

للبناء المحلي التجاري، أنشئ `android/key.properties` من المثال وضع keystore المطابق في `android/app/keystore/`. هذه الملفات مستبعدة من Git عمدًا.

## ملاحظة أمنية

المفتاح العام داخل التطبيق لا يمكنه إصدار رموز جديدة؛ يستطيع التحقق فقط. إصدار أو تمديد التراخيص يحتاج المفتاح الخاص الإداري الموجود خارج التطبيق.
