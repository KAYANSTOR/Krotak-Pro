# Phase 5 — Salafni

## الحالة

🟡 منفذة في المستودع — بانتظار إغلاق بوابة CI والتحقق على جهاز Android حقيقي.

## الأساس التجاري

- طلب `سلفني` مقبول عبر `سلفني` أو `س` أو `s` أو `salafni`.
- المشترك يجب أن يكون مسجلًا ونشطًا.
- الرصيد يجب أن يكون صفرًا قبل إنشاء سلفة جديدة.
- لا توجد سلفة مفتوحة سابقة للمشترك.
- اختيار أقل فئة كروت نشطة لها مخزون متاح.
- حجز الكرت ثم تسجيل `TransactionType.advance` كدين في دفتر الحركات المشترك.
- بيع الكرت وتدقيق العملية في `AuditLogs`.
- رسالة قبول بعد الإصدار، ورسالة رفض عند رفض الطلب، ورسالة تسوية عند السداد.
- طلب الإصدار Idempotent بواسطة مرجع العملية.
- السداد Idempotent بواسطة مرجع التحويل، ويُطبق قبل بيع الكرت في أول تحويل مؤهل لاحق.
- عند وجود مبلغ متبقٍ بعد السداد، لا يُخصم الدين إلا إذا كان المتبقي يطابق فئة كرت نشطة واحدة؛ لتجنب إدخال مبلغ غير مؤهل في الدفتر.
- بعد تحقق السداد، المبلغ المتبقي فقط يدخل المسار التجاري المعتاد للتحويل والكرت.

## الإعدادات

- `salafni_enabled`
- `salafni_template_accepted`
- `salafni_template_rejected`
- `salafni_template_settled`

واجهة الإعدادات تعرض بطاقة تفعيل الخدمة وشاشة منفصلة لقوالب الرسائل.

## المتغيرات في القوالب

`{amount}` `{serial}` `{code}` `{reason}` `{remaining}`

## التحقق المطلوب قبل Production Ready

1. `dart analyze lib test`
2. `flutter analyze --no-fatal-infos`
3. `flutter test`
4. `flutter build apk --debug`
5. جهاز Android حقيقي: طلب سلفني، إصدار الكرت، إعادة نفس الطلب، فشل الإرسال، ثم أول تحويل للتسوية، ثم إعادة نفس التحويل.
6. التأكد من عدم وجود خصم مزدوج أو كرت مزدوج أو حركة مالية موازية.
