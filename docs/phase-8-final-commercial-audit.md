# المرحلة 8 — Final Commercial Audit

**التاريخ:** 2026-09-21  
**الفرع:** `development/full-completion`  
**الحالة:** بروتوكول مفتوح — لا يُعلن الإصدار «جاهز تجاريًا» قبل إغلاق كل بند حرج

هذه المرحلة هي التالية في `docs/krotak-pro-full-completion-plan.md` (الأقسام 18–23). المراحل 1→PDF والمرحلة 7 (مسار CI) مكتملة برمجيًا.

---

## أ) ما لا يُغلق إلا على المالك / جهاز حقيقي

1. إضافة GitHub Secrets الأربعة ثم تشغيل `workflow_dispatch` ناجح لـ `build-apk`.
2. تثبيت APK الإصدار على جهاز Android حقيقي.
3. صلاحيات: SMS · Notification Listener · تجاهل تحسين البطارية · Boot.
4. استقبال SMS حقيقي + إرسال SMS حقيقي.
5. إعادة تشغيل الهاتف ثم استئناف Worker بلا تكرار مالي.
6. استيراد PDF / XLSX / CSV حقيقي + رفض TXT/صور.
7. مسارات POS الثلاثة + سقف الدين + حد طلبات الرصيد + سلفني للعملاء فقط.
8. اقتراحات الجوال في البيع المباشر وتعديل رصيد العميل.
9. تصدير PDF/كشف + مشاركة نظامية.
10. Backup / Restore بلا فقدان دفتر أو مخزون.
11. التحقق أن APK الموقَّع بنفس المفتاح يثبَّت فوق النسخة المثبَّتة.

---

## ب) بوابة الإصدار (نسخ من الخطة § 23)

| البند | الحالة الحالية |
|------|------------------|
| `flutter analyze --no-fatal-infos` | يُغلق على CI بعد الدفع |
| `flutter test` | يُغلق على CI بعد الدفع |
| Release APK موقَّع من Secrets | ينتظر الأسرار |
| CI ناجح كاملاً | ينتظر الأسرار |
| جهاز Android حقيقي | مفتوح |
| SMS وارد/صادر حقيقي | مفتوح |
| إعادة تشغيل الهاتف | مفتوح |
| استيراد الأنواع الثلاثة + الرفض | منطق موجود — يحتاج ملفاً حقيقياً |
| POS credit / quota / 3 قوالب / سلفني | اختبارات Domain موجودة — جهاز مفتوح |
| اقتراحات + تعديل رصيد | اختبارات Domain موجودة — جهاز مفتوح |
| إدارة المباعة + تصدير | منطق موجود — جهاز مفتوح |
| Backup/Restore | جهاز مفتوح |
| لا أسرار في لوحات CI | مكتمل في workflow الفرع |
| لا مفتاح إنتاج مودَع كاحتياط CI | مكتمل — الملف القديم مؤجل لقرار التدوير |

**الحكم الحالي:** غير جاهز للنشر التجاري — ينتظر الأسرار + أدلة الجهاز.

---

## ج) بروتوكول المشغِّل (جهاز)

1. بناء APK من CI بعد وضع الأسرار، أو `flutter build apk --release` مع `android/key.properties` محلي.
2. تثبيت فوق النسخة السابقة إن وُجدت — لا رسالة «التوقيع غير متطابق».
3. منح الصلاحيات ثم إغلاق شاشة التحقق / قائمة `docs/launch-readiness-checklist.md`.
4. تصدير حزمة الأدلة من التطبيق ورفعها في المستودع تحت `docs/evidence/` إن لزم (بلا أرقام كروت أو هواتف حقيقية).
5. تحديث هذا الملف: نجاح / فشل + فجوات متبقية صريحة.

## د) قواعد الإعلان

لا يُكتب في المستودع «جاهز للنشر التجاري» إلا بعد:

- صف جدول البوابة أعلاه.
- حزمة أدلة جهاز.
- عدم وجود فجوة P0 مفتوحة.
