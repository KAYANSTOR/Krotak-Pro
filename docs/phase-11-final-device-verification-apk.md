# Phase 11 — تحقق جهاز نهائي + APK

**تاريخ:** 2026-09-17  
**الحالة:** منفذة برمجياً — الإغلاق النهائي مشروط بجهاز Android حقيقي وحزمة أدلة  
**المصدر:** خطة المطابقة 100% + progress.md + بروتوكول Phase 19

## الهدف

إغلاق المرحلة الأخيرة من خطة المطابقة: تدقيق بصري للشاشات المغلقة برمجياً، تشغيل بوابات التحقق على جهاز حقيقي، بناء APK إصدار، وحفظ حزمة الأدلة.

لا تُخترع نتائج جهاز من CI أو المحاكي.

## ما نُفّذ برمجياً في هذه المرحلة

- بوابات تدقيق بصري في `DeviceVerificationCatalog`:
  - `visual_cards` — شاشة الكروت والفئات والاستيراد
  - `visual_reports_pos` — التقارير وتسوية نقاط البيع
  - `visual_direct_sale` — البيع المباشر (نقدي / آجل / هدية / POS)
  - `visual_offers` — العروض الترويجية
  - `visual_system_check` — فحص النظام والصيانة
- حزمة الأدلة `exportEvidencePack` تحمل `matchingPhase: 11` مع البوابات الجديدة.
- رقم الإصدار: `1.0.11+11` في `pubspec.yaml`.
- CI يبني `flutter build apk --release` ويرفع الأثر على GitHub Releases.

## بروتوكول المشغّل (جهاز حقيقي)

1. تثبيت APK الإصدار من GitHub Actions / `flutter build apk --release`.
2. منح صلاحيات SMS + تجاهل تحسين البطارية + Notification Listener إن لزم.
3. تشغيل البوابات التشغيلية السابقة (وتسجيل الملاحظات/المقاييس).
4. التدقيق البصري في الوضعين الفاتح والداكن للشاشات الخمس.
5. من الإعدادات → تحقق الجهاز: تعليم كل بوابة «تم على الجهاز».
6. نسخ حزمة الأدلة وحفظها مع رقم الـ APK.

## معيار الإغلاق

- `readyForRelease == true` على الجهاز.
- APK إصدار `1.0.11+11`.
- حزمة JSON من الشاشة، ليست مولّدة يدوياً في المستودع.

## خارج النطاق

- تشغيل البوابات من CI.
- نشر تلقائي على Google Play.
- اختراع لقطات أو مقاييس جهاز.
